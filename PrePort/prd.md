# PRD: 개발자 프로필 웹사이트 (PrePort)

## 1. 개요

| 항목 | 내용 |
|------|------|
| 프로젝트명 | PrePort |
| 목적 | 전장(차량 전자장치) 검증 엔지니어의 경력·역량·프로젝트를 소개하는 개인 프로필 웹사이트 |
| 연락처 | aaa@gmail.com |
| 주 업무 분야 | 전장 검증 (Automotive E/E Validation) |
| 문서 버전 | v0.1 (2026-11-03) |

## 2. 배경 및 목표

### 2.1 배경
- 전장 검증 업무는 결과물이 사내 시스템·차량에 묻혀 외부에 드러나기 어렵다.
- 이력서 한 장으로는 검증 범위, 사용 툴, 프로젝트 기여도를 충분히 보여주기 어렵다.

### 2.2 목표
1. 채용 담당자·협업 파트너가 **3분 안에** 핵심 역량과 경력을 파악할 수 있게 한다.
2. 전장 검증 전문성(프로토콜, 툴체인, 표준 대응 경험)을 구조적으로 보여준다.
3. 이메일로 바로 연락할 수 있는 동선을 제공한다.

### 2.3 비목표 (Out of Scope)
- 블로그/CMS 기능, 로그인·회원 기능
- 다국어 자동 번역 (1차는 한국어, 영어는 추후 검토)
- 사내 기밀 자료(사양서, 실제 로그 등) 게시

## 3. 타깃 사용자

| 사용자 | 니즈 |
|--------|------|
| 채용 담당자 / 헤드헌터 | 경력 요약, 보유 기술, 연락처를 빠르게 확인 |
| 기술 면접관 / 팀 리드 | 검증 방법론, 사용 툴, 프로젝트 상세 기여도 확인 |
| 협업 파트너 / 업계 지인 | 전문 분야 확인 및 연락 |

| 5 | Projects | 대표 검증 프로젝트 카드 (대상 제어기, 검증 범위, 사용 툴, 성과) | P0 |

### 4.2 Skills 섹션 분류 (예시 콘텐츠)

- **통신 프로토콜**: CAN, CAN-FD, LIN, Automotive Ethernet, FlexRay, UDS(ISO 14229), DoIP
- **검증 툴**: Vector CANoe / CANalyzer, CAPL, dSPACE, HILS/SILS 환경, Trace32
- **검증 방법론**: 요구사항 기반 테스트, 블랙박스/화이트박스 테스트, 회귀 테스트, 테스트 자동화
- **표준/프로세스**: ISO 26262(기능안전), ASPICE, AUTOSAR 이해
- **자동화/스크립트**: Python, CAPL, CI 연동 테스트 자동화
- **관리 도구**: JIRA, Polarion, DOORS 등 요구사항·결함 관리 툴

> 각 항목은 숙련도(예: 실무 주도 / 실무 사용 / 기초) 3단계로 표기한다.

### 4.3 Projects 카드 필드
- 프로젝트명 / 기간
- 대상 시스템 (예: BCM, ADAS ECU, 인포테인먼트, 배터리 관리 시스템 등)
- 담당 역할 및 검증 범위
- 사용 툴·환경
- 정량 성과 (예: 테스트 케이스 N건 작성, 자동화로 검증 시간 X% 단축, 결함 N건 사전 검출)
- 기밀 정보는 일반화하여 기술
