## 1. 개요

### 1.1 배경
할 일 관리 앱은 기능이 많아 정작 "오늘 무엇을 할지"에 집중하기 어렵다. 이 페이지는 **오늘 하루의 할 일만** 빠르게 적고, 체크하고, 진행률을 보는 데 집중한다.

### 1.2 목표
- 3초 안에 할 일 하나를 추가할 수 있다.
- 오늘 얼마나 해냈는지 한눈에 보인다 (진행률).
- 브라우저를 닫았다 열어도 데이터가 유지된다.
- 설치 없이 `index.html` 파일 하나를 열면 바로 동작한다.

### 1.3 비목표 (이번 범위 아님)
- 회원가입·로그인, 서버 동기화, 여러 기기 공유
- 프로젝트/태그/하위 작업 같은 복잡한 분류
- 알림(푸시), 반복 일정, 캘린더 연동

## 2. 분석

### 2.1 대상 사용자
| 페르소나 | 특징 | 핵심 니즈 |
|---|---|---|
| 직장인 | 출근 직후 하루 계획을 세움 | 빠른 입력, 우선순위 표시 |
| 학생 | 과제·공부 분량을 쪼개서 관리 | 완료 체크의 성취감, 진행률 |
| 일반 사용자 | 장보기·집안일 메모 | 단순함, 모바일에서도 편한 사용 |

### 2.2 사용자 시나리오
1. 아침에 페이지를 열면 오늘 날짜와 빈 목록(또는 어제 못 끝낸 일)이 보인다.
2. 입력창에 "보고서 초안 작성"을 입력하고 Enter → 목록 맨 위에 추가된다.
3. 중요한 일은 우선순위를 "높음"으로 표시한다.
4. 일을 마치면 체크박스를 누른다 → 줄이 그어지고 진행률이 오른다.
5. 오타가 있으면 항목을 더블클릭해 수정한다.
6. 다음 날 페이지를 열면 어제 못 끝낸 일을 오늘로 가져올지 물어본다.

### 2.3 기능 요구사항

| ID | 기능 | 설명 | 우선순위 |
|---|---|---|---|
| F-01 | 할 일 추가 | 입력 후 Enter 또는 추가 버튼. 빈 값·공백만 있는 값은 추가하지 않음. 최대 100자 | 필수 |
| F-02 | 완료 토글 | 체크박스 클릭으로 완료/미완료 전환. 완료 항목은 취소선 + 흐리게 | 필수 |
| F-03 | 할 일 수정 | 더블클릭(모바일: 수정 버튼)으로 인라인 편집. Enter 저장, Esc 취소 | 필수 |
| F-04 | 할 일 삭제 | 항목별 삭제 버튼. 삭제 직후 5초간 "되돌리기" 제공 | 필수 |
| F-05 | 진행률 표시 | "완료 3 / 전체 5 (60%)" 텍스트 + 진행 막대 | 필수 |
| F-06 | 오늘 날짜 표시 | 상단에 "2026년 11월 2일 (월)" 형식 | 필수 |
| F-07 | 데이터 저장 | localStorage에 자동 저장, 새로고침해도 유지 | 필수 |
| F-08 | 필터 | 전체 / 진행 중 / 완료 탭 | 권장 |
| F-09 | 우선순위 | 높음 / 보통 / 낮음. 색상 점으로 표시, 높음이 위로 정렬 | 권장 |
| F-10 | 완료 항목 일괄 삭제 | "완료된 항목 지우기" 버튼 (확인 후 실행) | 권장 |
| F-11 | 어제 미완료 이월 | 날짜가 바뀌면 이전 날짜의 미완료 항목을 오늘로 옮길지 배너로 안내 | 권장 |
| F-12 | 순서 변경 | 드래그 앤 드롭으로 순서 바꾸기 | 선택 |
| F-13 | 다크 모드 | 시스템 설정 따름 + 수동 전환 버튼 | 선택 |

### 2.4 비기능 요구사항

| ID | 항목 | 기준 |
|---|---|---|
| N-01 | 성능 | 항목 200개에서도 추가·토글 반응 100ms 이내 |
| N-02 | 호환성 | 최신 Chrome, Edge, Safari, Firefox |
| N-03 | 반응형 | 360px(모바일) ~ 1440px(데스크톱), 가로 스크롤 없음 |
| N-04 | 접근성 | 키보드만으로 모든 기능 사용 가능, 체크박스·버튼에 레이블, 색 대비 4.5:1 이상 |
| N-05 | 안정성 | localStorage를 쓸 수 없는 환경(사생활 보호 모드 등)에서도 화면은 동작하고 "저장되지 않음" 안내 |
| N-06 | 보안 | 사용자 입력은 `textContent`로만 출력 (innerHTML 사용 금지, XSS 방지) |
| N-07 | 배포 | 정적 파일만으로 동작 (서버 불필요) |

### 2.5 제약 및 가정
- 데이터는 사용자의 브라우저에만 저장된다 (기기 간 공유 안 됨).
- "오늘"의 기준은 사용자 기기의 로컬 시간 자정이다.
- localStorage 용량(약 5MB)은 할 일 텍스트 수천 개에 충분하다.

## 3. 설계

### 3.1 파일 구조
```
todolist/
├── prd.md          # 이 문서
├── index.html      # 화면 뼈대
├── css/
│   └── style.css   # 스타일, 테마 변수, 반응형
└── js/
    ├── storage.js  # localStorage 읽기/쓰기
    ├── store.js    # 상태와 상태 변경 함수
    ├── view.js     # 화면 그리기
    └── app.js      # 이벤트 연결, 시작점
```
`<script type="module">`로 불러온다. 단, 파일을 더블클릭해 `file://`로 열면 모듈이 막히는 브라우저가 있으므로, **구현 단계에서 하나의 `app.js`로 합칠지** 결정한다 (권장: 단일 파일 시작 → 커지면 분리).

### 3.2 화면 설계 (와이어프레임)

**데스크톱 (최대 너비 640px, 가운데 정렬)**
```
┌──────────────────────────────────────────────┐
│  오늘의 할일                          [🌙]    │
│  2026년 11월 2일 (월)                         │
├──────────────────────────────────────────────┤
│  ┌ 어제 못 끝낸 일 2개가 있어요 [가져오기][닫기] ┐│  ← F-11 (조건부)
├──────────────────────────────────────────────┤
│  [ 할 일을 입력하세요...      ] [보통 ▾] [추가] │
├──────────────────────────────────────────────┤
│  완료 3 / 전체 5                       60%    │
│  ████████████░░░░░░░░                         │
├──────────────────────────────────────────────┤
│  [전체] [진행 중] [완료]                       │
├──────────────────────────────────────────────┤
│  ☐ ● 보고서 초안 작성                [✎][🗑]  │  ● 빨강 = 높음
│  ☐ ● 장보기                          [✎][🗑]  │  ● 노랑 = 보통
│  ☑ ● ~~메일 답장~~                    [✎][🗑]  │
├──────────────────────────────────────────────┤
│                        [완료된 항목 지우기]    │
└──────────────────────────────────────────────┘
          ┌ 삭제했어요  [되돌리기] ┐               ← 토스트 (5초)
```

**모바일 (360px)**
- 입력창이 한 줄 전체, 우선순위·추가 버튼은 그 아래 줄로 내려간다.
- 수정·삭제 버튼은 항상 보이게 한다 (데스크톱은 마우스를 올렸을 때 표시).
- 터치 영역은 최소 44×44px.

**빈 상태**: 목록이 비면 "오늘 할 일을 추가해 보세요" 안내 문구를 보여준다. 필터 결과가 비면 "완료한 일이 아직 없어요" 등 필터별 문구를 보여준다.

### 3.3 데이터 모델

```js
// 할 일 하나
Todo = {
  id: string,          // crypto.randomUUID() (없으면 Date.now()+난수)
  text: string,        // 1~100자, 앞뒤 공백 제거
  done: boolean,
  priority: "high" | "normal" | "low",
  date: "YYYY-MM-DD",  // 이 할 일이 속한 날짜 (로컬 시간)
  order: number,       // 정렬용, 작을수록 위
  createdAt: number,   // ms timestamp
  doneAt: number|null
}

// localStorage 저장 형태 (키 하나)
key: "today-todo:v1"
value: {
  version: 1,
  todos: Todo[],
  settings: { theme: "system" | "light" | "dark", filter: "all" | "active" | "done" }
}
```
- `version`을 두어 나중에 구조가 바뀌면 이전 데이터를 변환할 수 있게 한다.
- 화면에는 `date === 오늘`인 항목만 보여준다. 이전 날짜 항목은 이월 판단에만 쓴다.
- 30일이 지난 완료 항목은 앱 시작 시 정리한다 (저장 공간 관리).

### 3.4 상태 관리 설계
단방향 흐름: **이벤트 → 상태 변경 함수 → 저장 → 다시 그리기**

```
[사용자 입력] → app.js(이벤트 핸들러)
                 → store.js: addTodo / toggleTodo / editTodo / removeTodo / setFilter ...
                     → storage.js: save(state)
                     → view.js: render(state)
```

| 함수 | 역할 |
|---|---|
| `addTodo(text, priority)` | 검증 후 맨 위(order 최소)에 추가 |
| `toggleTodo(id)` | done 반전, doneAt 기록/해제 |
| `editTodo(id, text)` | 검증 후 텍스트 변경 (빈 값이면 변경 취소) |
| `removeTodo(id)` | 삭제하고 되돌리기용으로 마지막 삭제 항목 보관 |
| `undoRemove()` | 보관한 항목을 원래 위치로 복구 |
| `clearDone()` | 오늘 날짜의 완료 항목 일괄 삭제 |
| `setFilter(f)` / `setTheme(t)` | 설정 변경 |
| `carryOver()` | 이전 날짜 미완료 항목의 date를 오늘로 변경 |
| `getVisibleTodos()` | 오늘 + 필터 적용 + 정렬(우선순위 → order) |
| `getProgress()` | `{ done, total, percent }` (total 0이면 0%) |

### 3.5 화면 그리기 설계
- 목록은 상태가 바뀔 때마다 `<ul>`을 다시 그린다 (항목 수가 적어 충분히 빠름, N-01).
- 항목 DOM은 `<template>`을 복제해 만들고 텍스트는 `textContent`로 넣는다 (N-06).
- 이벤트는 `<ul>` 하나에 위임해서 처리한다 (`data-id`, `data-action` 속성 사용).
- 인라인 수정 중에는 다시 그리기로 입력창이 사라지지 않도록 편집 중인 id를 상태에 둔다.

### 3.6 주요 흐름

**앱 시작**
```
load() → 데이터 없음/깨짐? → 기본값으로 시작 (깨진 경우 콘솔 경고)
       → 30일 지난 완료 항목 정리
       → 이전 날짜 미완료 항목 있음? → 이월 배너 표시
       → render()
```

**날짜가 바뀌는 경우**: 페이지를 연 채로 자정이 지나면 1분마다 날짜를 확인해서, 바뀌었으면 날짜 표시를 갱신하고 이월 배너를 띄운다. 탭이 다시 보일 때(`visibilitychange`)도 확인한다.

### 3.7 디자인 가이드
| 항목 | 값 |
|---|---|
| 글꼴 | `"Pretendard", "Malgun Gothic", system-ui, sans-serif` |
| 기본 크기 | 본문 16px, 제목 24px |
| 색상 변수 | `--bg`, `--surface`, `--text`, `--muted`, `--accent`, `--danger`, `--prio-high`, `--prio-normal`, `--prio-low` |
| 다크 모드 | `prefers-color-scheme` + `[data-theme]` 속성으로 덮어쓰기 |
| 애니메이션 | 추가·삭제 시 150ms 페이드, `prefers-reduced-motion`이면 끔 |

### 3.8 키보드·접근성
| 키 | 동작 |
|---|---|
| `/` 또는 `N` | 입력창으로 이동 |
| Enter | 추가 / 수정 저장 |
| Esc | 수정 취소 |
| Tab | 항목 → 체크박스 → 수정 → 삭제 순서로 이동 |
| Space | 포커스된 체크박스 토글 |
- 진행률 막대는 `role="progressbar"`와 `aria-valuenow`를 사용한다.
- 토스트와 이월 배너는 `aria-live="polite"`로 화면 읽기 프로그램에 알린다.

### 3.9 예외 처리
| 상황 | 처리 |
|---|---|
| 빈 값 / 공백만 입력 | 추가하지 않고 입력창을 흔드는 효과 + 안내 |
| 100자 초과 | `maxlength`로 입력 제한 |
| localStorage 사용 불가 | 메모리에서만 동작, 상단에 "이 브라우저에서는 저장되지 않아요" 표시 |
| 저장 데이터 손상(JSON 오류) | 기본값으로 시작, 손상된 원본은 `today-todo:backup` 키에 보관 |
| 저장 공간 초과 | 토스트로 안내, 오래된 완료 항목 정리 제안 |

## 4. 인수 기준 (구현 후 확인할 항목)
- [ ] 할 일을 입력하고 Enter를 누르면 목록 맨 위에 나타난다.
- [ ] 체크하면 취소선이 생기고 진행률 숫자와 막대가 즉시 바뀐다.
- [ ] 새로고침해도 목록, 완료 상태, 필터, 테마가 그대로다.
- [ ] 삭제 후 5초 안에 되돌리기를 누르면 원래 자리로 돌아온다.
- [ ] `<b>test</b>`를 입력하면 굵은 글씨가 아니라 글자 그대로 보인다.
- [ ] 시스템 날짜를 다음 날로 바꾸고 열면 이월 배너가 나타난다.
- [ ] 360px 너비에서 가로 스크롤 없이 모든 기능을 쓸 수 있다.
- [ ] 마우스 없이 키보드만으로 추가·완료·수정·삭제가 된다.
